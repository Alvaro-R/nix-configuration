# AGENTS.md — How this Mac is managed

This repository is the single source of truth for the machine `Ecthelion`
(Apple Silicon, `aarch64-darwin`, user `alvaroroman`). Everything installed or
configured on it must be declared here.

## Golden rule

NEVER install, remove, or configure software imperatively (`brew install`,
`brew uninstall`, `npm install -g`, `curl ... | sh`, `mas install`, editing
`defaults` by hand). Declare the change in this repo and apply it with a rebuild.

Homebrew runs with `onActivation.cleanup = "zap"`: anything installed by hand
that is not declared here is REMOVED on the next rebuild.

## Layout

| File | Purpose |
| --- | --- |
| `flake.nix` | nix-darwin system config: inputs, Nix packages, Homebrew, macOS defaults |
| `home.nix` | Home Manager (user `alvaroroman`): user packages, dotfiles, activation scripts |
| `skills/` | Agent skills deployed globally via `home.file` in `home.nix` |
| `flake.lock` | Pinned input versions |
| `.engram/config.json` | Pins the Engram memory project to `mac-configuration` |

## Where to declare each thing

| What | Where |
| --- | --- |
| CLI tool available in nixpkgs (system-wide) | `flake.nix` → `environment.systemPackages` |
| CLI tool for the user only | `home.nix` → `home.packages` |
| Homebrew formula | `flake.nix` → `homebrew.brews` |
| Formula from a third-party tap | `flake.nix` → `homebrew.taps` (with `trusted = true`) + `homebrew.brews` |
| GUI app (cask) | `flake.nix` → `homebrew.casks` |
| Mac App Store app | `flake.nix` → `homebrew.masApps` (`"Name" = <id>;`, find id with `mas search`) |
| macOS settings (Dock, Finder, etc.) | `flake.nix` → `system.defaults` |
| Self-updating tool with official installer (e.g. Claude Code) | `home.nix` → `selfUpdatingTools` |
| Global npm package | `home.nix` → `npmGlobalPackages` (and `npmAllowScripts` if it needs install scripts) |
| Dotfiles / config files | `home.nix` → `home.file` |

Prefer nixpkgs when the package exists and is up to date; use Homebrew for GUI
apps and tools that are missing or stale in nixpkgs.

When removing something, comment it out with a short reason (existing
convention), e.g. `# "cursor" -- not used`.

## Apply changes

```sh
cd ~/.config/nix/nix-darwin
git add -A   # flakes only see files tracked by git
sudo darwin-rebuild switch --flake .#Ecthelion
```

- Build without activating: `darwin-rebuild build --flake .#Ecthelion`
- Update inputs: `nix flake update`, then rebuild.
- Format Nix files with `alejandra .`
- No separate `home-manager switch`: `darwin-rebuild` applies `home.nix` too.

## Keep docs, skills, and agent config in sync (MANDATORY)

Any change to how this machine is managed must update, in the SAME commit:

- `AGENTS.md` (this file): layout, "where to declare" table, apply commands,
  conventions.
- `skills/*/SKILL.md`: rules and commands that duplicate this file (repo path,
  rebuild command, golden rule).
- `home.nix` → `agentSkills` / `agentSkillDirs`: when a skill is added or
  renamed, or an agent with a global skills directory is added or removed.

Triggers: new or moved config file/module, new kind of managed software or
mechanism (e.g. a new activation script or list in `home.nix`), changed
hostname/user/rebuild command, new or removed AI agent, changed conventions.

Not a trigger: adding or removing a single package/app in an existing list.

Before finishing any change, check these three places and state in the reply
whether they were updated or why no update was needed.

## Conventions

- Conventional Commits (`feat(homebrew): ...`, `fix(home): ...`), no AI attribution.
- Keep comments in code explaining non-obvious choices.
- Agent instruction files (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`,
  `~/.config/opencode/AGENTS.md`) are generated by gentle-ai; do not edit them
  by hand. Machine-management knowledge lives here.
